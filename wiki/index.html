SDK architecture how the pieces fit together

cuQuantum follows a three-layer model. Quantum frameworks (Qiskit, Cirq, PennyLane, CUDA-Q…) sit on top. They (optionally via the cuquantum Python package) call into one of five purpose-built CUDA libraries, each tuned for a different simulation paradigm. Those libraries in turn lean on lower-level primitives — cuBLAS, cuTENSOR, cuSPARSE, NCCL, MPI.

cuStateVec cuTensorNet cuDensityMat cuPauliProp cuStabilizer

Library map pick the right tool for the simulation paradigm

LibraryParadigmBest forScales toState representation

cuTensorNet Tensor networks · MPS / MPO Low-entanglement circuits, expectation values, amplitudes 100s–1000s of qubits if structure permits Network of small tensors
cuDensityMat Density matrix / Lindblad Open quantum systems, noisy dynamics, MPS-TDVP Smaller Hilbert spaces; MPS form for larger ρ, MPS, or matrix-product operators

Heuristic: if the circuit is dominated by Clifford gates → cuStabilizer; low entanglement → cuTensorNet; noise modeling → cuDensityMat; observables only → cuPauliProp; everything else → cuStateVec.

cuStateVec full state-vector simulation

cuStateVec accelerates the canonical model: keep the full complex state vector \( |\psi\rangle \in \mathbb{C}^{2^n} \) on the GPU(s) and apply gates as in-place sparse-matrix updates. Memory is the bottleneck — a 30-qubit fp64 statevector is 16 GiB; scaling beyond requires multi-GPU + MPI.

Core algorithms

Gate application kernel

For a k-qubit gate with target indices \(t_1,\dots,t_k\), the kernel iterates over all \(2^{n-k}\) "outer" indices, gathers the \(2^k\) inner amplitudes, multiplies by the gate matrix (cached in shared memory), and scatters them back. Single-qubit gates collapse to the well-known strided pair update.

Batched / controlled gates

Controls are implemented by skipping outer indices whose control bits don't match — no extra memory traffic. batched_gate_application.cu applies different gates per batch index in one launch, which is the primitive backing variational/expectation pipelines.

Pauli exponentials

ApplyExpPauli exploits the structure of \(e^{i\theta P}\) for a Pauli string \(P\): only \(\cos\theta\,I + i\sin\theta\,P\) terms appear, so the kernel is two passes over the relevant index pairs, no dense matrix.

Sampling

cuStateVec builds a cumulative |amplitude|² table (parallel prefix-sum) and binary-searches sorted random draws into it — the foundation of custatevecSampler and the multi-GPU sibling mgpu_sampler.

Multi-GPU strategy

The state vector is distributed across GPUs by "global index bits". Gates acting only on local index bits are pure compute; gates touching global bits require a swap-index-bit collective (cuStateVec ships an explicit SwapIndexBits primitive) followed by a local gate apply.

Where it lives

  • C/C++ samples: samples/custatevec/custatevec/*.cu & samples/custatevec/custatevecex/
  • Python low-level binding: python/cuquantum/bindings/custatevec.pyx + cycustatevec.pyx
  • Distribution: custatevec-cu12 / custatevec-cu13 on PyPI; custatevec on conda-forge.

cuTensorNet tensor networks · contraction · MPS

cuTensorNet treats a quantum circuit as a tensor network and answers queries (amplitudes, marginals, expectations, samples) by contracting it. Two API surfaces are exposed: a legacy low-level "build a network, find a path, contract slices" flow, and a newer high-level network-state API (amplitudes / sampling / expectation / MPS / DMRG).

Algorithm pipeline

The optimizer (step 2) is the heart: it searches for a contraction order with small intermediate tensors. Large/expensive intermediates get sliced — fixed indices that turn one contraction into many smaller, embarrassingly parallel ones, perfect for slice-based MPI distribution (tensornet_example_mpi.cu).

The contraction-path finder

The optimizer combines greedy / dynamic programming over the network's line graph, branch-and-bound for sub-trees, and reinforcement-learning-style sampling. Configuration (sampler, seed, slicing target memory) is set via cutensornetContractionOptimizerConfigSetAttribute; results are encapsulated in a serializable cutensornetContractionOptimizerInfo_t that can be broadcast over MPI (see the explicit-MPI sample).

Gradient via reverse-mode

tensornet_example_gradients.cu marks selected input tensors for gradient tracking, allocates a CUTENSORNET_WORKSPACE_CACHE to hold intermediates from the forward contraction, then calls cutensornetNetworkComputeGradientsBackward. The cache must be WorkspacePurgeCache'd between calls — that's the only stateful step.

cuDensityMat open-system dynamics · Lindblad · MPS-TDVP

cuDensityMat targets the master equation \(\dot\rho = -i[H,\rho] + \sum_k \mathcal{L}_k\rho\), where \(\mathcal{L}_k\) are Lindblad superoperators. It exposes operators as compositions of elementary tensors, MPOs, or callable kernels, and computes their action on a state — never explicitly building the (potentially huge) full superoperator.

How operator action is computed

An operator is stored as a DAG of tensor contractions over site indices. At application time, cuDensityMat fuses the per-site tensors with ρ, dispatches contractions through cuTENSOR, and accumulates results. For time-dependent terms, Python callbacks are invoked to refresh coefficients between time steps; for time-independent dense ops the contraction plan is cached.

TDVP projects \(\dot{|\psi\rangle} = -iH|\psi\rangle\) onto the MPS manifold of fixed bond dimension χ, integrating an effective ODE on the tangent space — cost \(\mathcal{O}(n\chi^3 d^2)\) per step instead of exponential in n.

cuPauliProp Heisenberg-picture Pauli propagation

Instead of evolving the state \(|\psi\rangle\) forward, cuPauliProp evolves an observable \(O = \sum_i c_i P_i\) backward through the circuit: \(O_{t-1} = U_t^\dagger O_t U_t\). Each unitary maps a Pauli string to a (usually short) sum of Pauli strings. For Clifford gates this is exact and keeps the number of terms constant; for non-Clifford gates (e.g. T, RZ(θ)) the operator splits, growing the sum. The library prunes by coefficient magnitude and operator weight — see truncation.py.

  • kicked_ising_backward_diff_example.cpp — same circuit with reverse-mode AD to compute gradients of ⟨O⟩ w.r.t. circuit parameters.

When to reach for cuPauliProp

  • You only need expectation values, not full amplitudes.
  • The observable is sparse in the Pauli basis (low operator weight).
  • The circuit is "near-Clifford" (few non-Clifford gates or shallow).
  • You want fast variational gradients without storing a state vector.

cuStabilizer Pauli-frame / Clifford simulation & QEC sampling

Stabilizer simulation (Gottesman–Knill) represents the state as a set of commuting Pauli operators that stabilize it. Clifford gates act as linear maps on a 2n × 2n binary tableau — polynomial in n. cuStabilizer adds: Pauli-frame tracking for fast Monte-Carlo simulation of stochastic Pauli noise; and Detector Error Model (DEM) sampling primitives used by QEC decoder workflows.

# custabilizer_demo.cpp — Bell state with bit-flip noise
Z_ERROR(0.3) 0     # Randomize Z bits of the frame on qubit 0
H 0                # Swap X and Z bits on qubit 0
CNOT 0 1           # X_target ^= X_control
M 1 2              # Measure qubits 1 and 2

How Pauli-frame simulation works

Start from a reference state (here |00⟩). A "frame" is a Pauli operator that, applied to the reference state, gives the noisy outcome. Each Clifford gate conjugates the frame (cheap bit-twiddles on the tableau). Stochastic Pauli noise simply XORs random bits into the frame. Measurement just reads the relevant bits. Result: noisy Monte-Carlo simulation at the cost of bit-vector ops, perfectly suited for massively parallel GPU sampling — which is what DEMSampler exploits for QEC decoder benchmarking.

End-to-end developer workflow

  1. Install: pick CUDA major version, then pip install cuquantum-python-cu13 (or cu12). Conda-forge users: conda install -c conda-forge cuquantum-python.
  2. Pick a paradigm (see library map).
  3. Prototype in Python: high-level API first (cuquantum.tensornet.experimental.NetworkState / cuquantum.densitymat.* / cuquantum.stabilizer.FrameSimulator).
  4. Profile with the benchmark suite; compare to other backends to make sure the choice of paradigm is right.
  5. Optimize: drop down to cuquantum.bindings.* or C/C++ when you need fine-grained control (custom optimizer config, custom memory pool, explicit MPI slicing).
  6. Scale out: MPI / NCCL for cuDensityMat & cuTensorNet; multi-GPU index-bit partitioning for cuStateVec; cusvaer backend for multi-node state-vector.

Glossary

State vector

Dense complex vector of dimension 2n for n qubits.

Density matrix (ρ)

2n × 2n Hermitian positive semi-definite operator representing mixed states.

MPS / MPO

Matrix Product State / Operator — efficient tensor-train representation for low-entanglement states / 1-D operators.

TDVP

Time-Dependent Variational Principle — symplectic integrator on a variational manifold (here, MPS of fixed χ).

Pauli string

Tensor product of single-qubit Paulis: \(P = \sigma_{a_1}\otimes\cdots\otimes\sigma_{a_n}\), ai∈{I,X,Y,Z}.

Clifford group

Unitaries that map Paulis to Paulis under conjugation. Generated by {H, S, CNOT}. Simulable in poly(n).

Stabilizer formalism

Track the group of Paulis that fix the state; Clifford gates act on it as a binary tableau.

DEM

Detector Error Model — graph/hypergraph relating physical noise events to syndrome detectors, used by QEC decoders.
